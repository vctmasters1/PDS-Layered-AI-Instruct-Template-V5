# PDS HAL Reorganization & Consolidation Guide

## Overview

The PDS Hardware Abstraction Layer has been reorganized to provide a **single consolidated include file** (`pds_hal.h`) that intelligently includes only the platform-appropriate subsystem headers.

## New Structure

```
pds_hal/
├── include/
│   ├── pds_hal.h                 # ⭐ NEW: Main consolidated HAL header
│   ├── pds_hal_config.h          # ⭐ NEW: Configuration header (auto-generated by CMake)
│   ├── pds_adc.h                 # Platform-agnostic ADC interface
│   ├── pds_pwm.h                 # Platform-agnostic PWM interface
│   ├── pds_gpio.h                # Platform-agnostic GPIO interface
│   ├── pds_spi.h                 # Platform-agnostic SPI interface
│   ├── pds_motor_DRV8833.h       # Platform-agnostic motor driver
│   └── pds_pins.h                # Pin management interface
│
├── pds_hal_core.c               # ⭐ NEW: HAL initialization & capability queries
```

## Usage

### Before (Old Way)

```c
#include "pds_adc.h"
#include "pds_pwm.h"
#include "pds_gpio.h"
#include "pds_motor_DRV8833.h"

esp_err_t result = PDS_ADC_init();
esp_err_t result = PDS_PWM_init();
esp_err_t result = PDS_GPIO_init();
```

### After (New Way)

```c
#include "pds_hal.h"  // ⭐ Single include!

// All subsystems are automatically included if available on this platform
// Initialize all enabled subsystems at once:
esp_err_t result = pds_hal_init();

// Or query capabilities:
if (pds_hal_is_available("MOTOR_DRV8833")) {
    pds_motor_drv8833_init(&config);
}
```

## How It Works

### 1. Platform Detection (CMakeLists.txt)

CMakeLists.txt detects the target platform at build time:

```cmake
if(IDF_TARGET STREQUAL "esp32c3")
    set(TARGET_PLATFORM "ESP32C3")
    set(PDS_HAL_CAPS 
        -DPDS_HAL_HAS_ADC=1
        -DPDS_HAL_HAS_PWM=1
        -DPDS_HAL_HAS_GPIO=1
        -DPDS_HAL_HAS_SPI=1
        -DPDS_HAL_HAS_MOTOR_DRV8833=1      # ⭐ Only ESP32-C3
        -DPDS_HAL_HAS_PINS=1
    )
elseif(IDF_TARGET STREQUAL "esp32")
    # Different capabilities for standard ESP32
    set(PDS_HAL_HAS_MOTOR_DRV8833 0)       # ⭐ Not available on ESP32
endif()
```

### 2. Conditional Compilation (pds_hal.h)

The main header uses preprocessor directives to include only appropriate subsystems:

```c
#if PDS_HAL_HAS_ADC
#include "pds_adc.h"
#endif

#if PDS_HAL_HAS_MOTOR_DRV8833
#include "pds_motor_DRV8833.h"  // Only included on ESP32-C3
#endif
```

### 3. Capability Queries (Runtime)

Check if a subsystem is available at runtime:

```c
if (pds_hal_is_available("MOTOR_DRV8833")) {
    // Motor driver available on this platform
} else {
    // Motor driver not available, use alternative approach
}

// Get platform info:
ESP_LOGI(TAG, "Platform: %s, HW: %s", 
    pds_hal_get_platform(),      // "ESP32C3"
    pds_hal_get_hwrev());        // "hwrev_001"
```

## Configuration

### Build-Time (in CMakeLists.txt)

Control which subsystems are compiled:

```cmake
# Custom capabilities for specific hardware revision
target_compile_definitions(${COMPONENT_LIB} PRIVATE
    -DPDS_HAL_HAS_MOTOR_DRV8833=1      # Enable motor driver
    -DPDS_HAL_HAS_SPI=0                # Disable if not used
)
```

### Runtime (in Application)

Initialize individual subsystems instead of all:

```c
// Initialize only specific subsystems
#if PDS_HAL_HAS_GPIO
pds_gpio_hal_init();
#endif

#if PDS_HAL_HAS_ADC
pds_adc_hal_init();
#endif

// Skip others for faster startup
```

## Initialization Order

`pds_hal_init()` initializes subsystems in this order:

1. **GPIO** (foundation - required by others)
2. **ADC** (may use GPIO)
3. **PWM** (may use GPIO)
4. **SPI** (independent)
5. **Pins** (uses GPIO, ADC, PWM)
6. **Motor Driver** (uses PWM and GPIO)

If any initialization fails, remaining subsystems are **not** initialized.

## Error Handling

```c
esp_err_t ret = pds_hal_init();

if (ret != ESP_OK) {
    ESP_LOGE(TAG, "HAL initialization failed: %s", esp_err_to_name(ret));
    // Determine which subsystem failed from logs
    return ret;
}
```

Check console output to identify which subsystem failed:

```
I (1234) PDS_HAL: GPIO subsystem initialized
I (2345) PDS_HAL: ADC subsystem initialized
E (3456) PDS_HAL: PWM initialization failed: ESP_ERR_INVALID_STATE
```

## Migration Guide

### For Application Code

**Before:**
```c
#include "pds_adc.h"
#include "pds_pwm.h"
#include "pds_motor_DRV8833.h"

void setup() {
    PDS_ADC_init();
    PDS_PWM_init();
    pds_gpio_hal_init();
    pds_motor_drv8833_init(&config);
}
```

**After:**
```c
#include "pds_hal.h"

void setup() {
    pds_hal_init();  // ⭐ One call initializes everything
}
```

### For Adding New Subsystems

1. Add header in `include/pds_xxx.h` (platform-agnostic interface)
2. Add implementation in `platform/{chip}/common/pds_xxx_{chip}.c`
3. Add capability flag to `pds_hal.h`:
   ```c
   #ifndef PDS_HAL_HAS_XXX
   #define PDS_HAL_HAS_XXX 0
   #endif
   ```
4. Add conditional include:
   ```c
   #if PDS_HAL_HAS_XXX
   #include "pds_xxx.h"
   #endif
   ```
5. Update CMakeLists.txt with platform capabilities
6. Add init stub to `pds_hal_core.c`:
   ```c
   __weak esp_err_t pds_xxx_hal_init(void) { return ESP_OK; }
   ```

## Benefits

### ✅ Cleaner Code
- Single `#include "pds_hal.h"` instead of multiple subsystem includes
- Application doesn't need to know what hardware it's running on

### ✅ Flexibility
- Easy to support multiple platforms from same codebase
- Unused subsystems don't get compiled (smaller binary)
- Runtime capability queries for conditional features

### ✅ Maintainability
- Central point to understand platform capabilities
- Clear initialization dependencies and order
- Self-documenting via capability matrix

### ✅ Extensibility
- Simple to add new subsystems
- Weak function pattern allows easy override
- CMakeLists.txt controls what gets compiled

## Troubleshooting

### "undefined reference to `pds_motor_drv8833_init`"

**Cause**: Motor driver header was included, but `PDS_HAL_HAS_MOTOR_DRV8833=0` in CMake.

**Solution**: Check `idf.py menuconfig` or CMakeLists.txt that motor driver is enabled:
```cmake
-DPDS_HAL_HAS_MOTOR_DRV8833=1
```

### "pds_hal_init() returns ESP_ERR_INVALID_STATE on GPIO"

**Cause**: GPIO subsystem initialization failed.

**Solution**: Check GPIO pin conflicts or hardware issues. See logs for details.

### "Motor driver functions not available"

**Cause**: Platform (ESP32) doesn't have motor driver.

**Solution**: Use runtime check:
```c
if (pds_hal_is_available("MOTOR_DRV8833")) {
    // Use motor driver
} else {
    // Use alternative (relay control, PWM directly, etc.)
}
```
