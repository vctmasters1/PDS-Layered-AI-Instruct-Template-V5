## IP Auto-Updates

Resume Suite automatically updates your DDNS domain with your current public IP.

### Automatic (Scheduled Task)
```powershell
# Setup (run once as Administrator)
./register-scheduled-task-dynu.ps1

# This registers "DynuUpdate-ResumeSuite" task
# - Runs every 5 minutes
# - Updates IP if changed
# - Logs to .dynu-update.log
```

### Manual
```powershell
# Run continuously in background
./dynu-update.ps1

# Or set interval
./dynu-update.ps1 -UpdateIntervalSeconds 300
```

### Check Logs
```bash
# View IP update history
Get-Content ResumeServer\.dynu-update.log

# Follow in real-time
Get-Content ResumeServer\.dynu-update.log -Wait
```

## Certificate Renewal

Caddy automatically renews Let's Encrypt certificates:
- Renewal attempts start 30 days before expiration
- HTTP-01 challenge requires port 80 accessible
- Logs available in: `docker compose logs caddy`

**To check cert validity:**
```bash
# View certificate expiration
openssl x509 -in certs/cert.pem -noout -dates

# Or via Docker
docker compose exec caddy caddy list-modules
```

## Troubleshooting

**Domain not resolving (DNS failing)**
```bash
# Test DNS
nslookup pds-resume-suite.mywire.org

# If it fails:
# 1. Wait 5-10 minutes (DNS propagation)
# 2. Check DDNS domain configuration on Dynu
# 3. Verify DYNU_TOKEN is correct
# 4. Manually update IP: ./dynu-update.ps1
```

**Certificate not auto-renewing**
```bash
# Check Caddy logs
docker compose logs caddy | grep -i "let's encrypt"

# Common issues:
# - Port 80 not accessible (Let's Encrypt can't verify)
# - DDNS domain doesn't resolve
# - Router firewall blocking Let's Encrypt callback

# Force manual renewal
docker compose exec caddy caddy reload
```

**IP not updating (DDNS stale)**
```bash
# Check update logs
Get-Content ResumeServer\.dynu-update.log

# Manual update
./dynu-update.ps1 -UpdateIntervalSeconds 60

# Verify token is valid
# https://www.dynu.com/ControlPanel/DynamicDNS/API
```

**External port forwarding not working**
```bash
# Verify from router admin (usually http://192.168.1.1)
# Check: External 80 → 192.168.1.80:80
#        External 443 → 192.168.1.80:443

# Test locally
netstat -ano | findstr :443

# Test from outside (ask friend to try URL)
```

**Users getting "connection refused"**
- Port forwarding not set up
- Windows Firewall blocking ports 80/443
- Caddy not running: `docker compose ps caddy`
- Services crashed: `docker compose logs`
