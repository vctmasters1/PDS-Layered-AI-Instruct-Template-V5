# .AI-Instruct.md — CSS Module Directory

> **Parent**: Refer to `marketplace/frontend/.AI-Instruct.md` for frontend architecture context and `marketplace/.AI-Instruct.md` for overall marketplace instructions.

## Directory Overview

This directory contains the **modular CSS architecture** for the PDS Marketplace frontend. All visual styles are split into focused, single-responsibility modules imported via `styles.css` (the master stylesheet at `marketplace/frontend/styles.css`).

## Import Order (Critical!)

The master stylesheet `marketplace/frontend/styles.css` imports modules in a **strict cascade order**:

1. **Foundation** — variables → buttons → layout
2. **Navigation** — navbar → mission → account
3. **Cards** — product → designer → producer
4. **Features** — dashboard → map → modals → cart → messaging → custom-projects → search → bulletin-board → portfolio → admin → footer
5. **Responsive** (MUST load last) — tablet → phone

**DO NOT reorder imports**. Responsive files rely on overriding earlier declarations via cascade priority.

## Rules for Editing

### Adding New Styles
1. **Identify the correct module** by component/feature. Never dump unrelated styles into an existing file.
2. If a feature doesn't fit any module, **create a new `_feature-name.css`** and add an `@import` to `styles.css` in the appropriate group (before responsive).
3. **Update this file's** inventory table when adding/removing modules.

### Responsive Overrides
- **Tablet** (≤768px): Add to `_tablet.css` only.
- **Phone** (≤480px): Add to `_phone.css` only.
- Never place `@media` queries inside component modules — all responsive rules live in the two responsive files.
- Exception: The hamburger toggle base (`.hamburger-btn { display: none; }`) lives at the top of `_tablet.css` because it's a non-media-query default.

### Card Modules
- Each entity type (product, designer, producer) has its own card file for **easy independent adjustment** per the user's request.
- Product cards also contain store cards and the image carousel since they share visual patterns.
- If a new entity type is added (e.g., Materials), create `_cards-materials.css`.

### Naming Conventions
- File prefix: `_` (partial/module convention)
- Class names: kebab-case (`.product-card`, `.designer-cta`, `.map-filters-bar`)
- CSS variables: declared in `_variables.css`, prefixed with `--` (e.g., `--bg-primary`, `--primary`)

### Theme / Dark Mode
- All colors MUST use CSS custom properties from `_variables.css`.
- Never hard-code hex colors in component files (except gradients that are decorative, e.g., card headers).
- Dark mode is handled via `prefers-color-scheme: dark` in `_variables.css`.

## Dependencies
- **Leaflet CSS** is loaded externally in `index.html` (not in this directory).
- **No CSS preprocessor** — all files are plain CSS using `@import url()`.
- **No build step** — files are served as-is via Express static middleware.

## Common Pitfalls
- **Duplicate selectors**: `.form-group` exists in both `_modals.css` (general) and `_admin.css` (admin-scoped override). The admin version uses `.admin-dashboard .form-group` for specificity.
- **`.btn-secondary`** is defined in both `_modals.css` and `_messaging.css` — the messaging version re-declares for proximity; consider consolidating into `_buttons.css` in a future cleanup.
- **`.badge`** is defined in both `_messaging.css` (round notification badge) and `_admin.css` (rectangular status badge). Context determines which applies.
