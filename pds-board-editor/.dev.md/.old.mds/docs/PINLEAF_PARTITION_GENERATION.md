# Pinleaf Forge Extended: Partition Configuration Generation

**Date**: April 16, 2026  
**Concept**: Pinleaf → Platform specs → Partition table generation  
**Status**: 🟡 **DESIGN - Ready for Pinleaf integration**

---

## Executive Summary

**Current Model**:  
Pinleaf exports → Pin definitions only (JSON)

**Proposed Model**:  
Pinleaf exports → Pin definitions + Partition table (JSON + CSV)

This makes Pinleaf the **single source of truth** for hardware configuration across all platforms, and automatically generates correct partition layouts for different flash sizes.

---

## Problem Statement

**Current Issues**:
1. Partitions.csv must be hand-configured per platform
2. Manual math error: "Is 20 KB NVS enough for ESP32-S3 16MB?"
3. Different platforms (ESP32, ESP32-C3, ESP32-S3), different flash sizes
4. No validation that device and config match

**Solution**:  
Let Pinleaf calculate partition layout based on platform specs.

## Partition Generation Algorithm

### Input Platform Specs
```
Flash size: 2,097,152 bytes (2 MB)
ESP-IDF version: 5.5.1
Use OTA: true (for field updates)
Config storage needed: 11 KB (PINMAP + LADDER + USRSET)
```

### Algorithm

```
Total Flash = 2 MB = 2,097,152 bytes

Allocate:
  Bootloader:   4 KB (0x0000-0x0FFF)        [Fixed]
  Partition tbl: 512 B (0x8000-0x81FF)      [Fixed]
  ────────────────────────────────────────
  Fixed overhead: 4.5 KB

  NVS:          20 KB (0x9000-0xDFFF)       [Config storage]
  OTA data:     8 KB (0xE000-0xFFFF)        [OTA metadata]
  ────────────────────────────────────────
  System: 28.5 KB

  Remaining: 2,097,152 - 28,672 = 2,068,480 bytes

  For OTA support (dual app):
    App0: 1,703,936 bytes (0x10000-0x1AFFFF)     [~81%]
    App1: 1,703,936 bytes (0x1B0000-0x2AFFFF)    [~81%]
    ────────────────────────────────────────
    Total app: ~1.6 MB (fits in 2 MB - 28.5 KB)

  Remaining free: ~661 KB (optional FATFS, etc.)
```

### Output partitions.csv

```csv
# Auto-generated by Pinleaf Forge for ESP32-C3 2MB
# Platform: ESP32-C3 RISC-V 160MHz, 400KB RAM, 2MB Flash
# Generated: 2026-04-16

# Name,   Type,   SubType,  Offset,  Size,      Flags
nvs,      data,   nvs,      0x9000,  0x5000,    ,
otadata,  data,   ota,      0xe000,  0x2000,    ,
app0,     app,    ota_0,    0x10000, 0x1a0000,  ,
app1,     app,    ota_1,    0x1b0000, 0x1a0000, ,
ffat,     data,   fat,      0x360000, 0xa0000,  ,
```

## Platform-Specific Generation

### ESP32-C3 (2 MB)
```
NVS: 20 KB
App: 1.7 MB (OTA dual)
Free: 660 KB
```

### ESP32-S3 (4 MB)
```
NVS: 20 KB
App: 1.7 MB (OTA dual = 3.4 MB)
Free: 580 KB
```

### ESP32 (4 MB)
```
NVS: 20 KB
App: 1.7 MB (OTA dual = 3.4 MB)
Free: 580 KB
```

### ESP32-C6 (8 MB)
```
NVS: 40 KB (headroom for larger configs)
App: 3 MB (OTA dual = 6 MB)
Free: 1.9 MB
```

### Pinleaf Strategy Options

```
1. "compact"       - Minimize app size (embedded systems)
   └─ NVS: 20 KB, App: 1 MB, OTA disabled
   
2. "balanced"      - Good tradeoff (DEFAULT)
   └─ NVS: 20 KB, App: 1.7 MB, OTA enabled
   
3. "app-heavy"     - Maximize app space (large firmware)
   └─ NVS: 20 KB, App: 3-4 MB, OTA disabled
   
4. "custom"        - User specifies sizes
   └─ UI sliders for each partition
```

## Device Validation

### Platform Signature in PINMAP

When Pinleaf generates PINMAP, include platform metadata:

```c
typedef struct {
    uint16_t version;
    uint8_t  num_pins;
    uint8_t  reserved;
    uint32_t checksum;
    
    // NEW: Platform validation
    uint32_t platform_id;              // ESP32-C3, ESP32-S3, etc.
    uint32_t flash_size;               // 2MB, 4MB, 8MB, etc.
    uint32_t expected_app_size;        // Firmware size limit
    
    pds_telconf_pinmap_entry_t pins[32];
} pds_telconf_pinmap_t;
```

### Device Boot Validation

```c
// On device startup:
if (pinmap.platform_id != MY_PLATFORM_ID) {
    ESP_LOGW(TAG, "PINMAP is for different platform!");
    ESP_LOGW(TAG, "Expected %s, got %s",
        platform_name(MY_PLATFORM_ID),
        platform_name(pinmap.platform_id));
    // Don't load - wait for correct PINMAP
}
```

## Questions

**Q: What if user changes flash size after uploading configs?**  
A: Device validates platform_id + flash_size in PINMAP. Rejects if mismatch.

**Q: Can we support external flash (PSRAM)?**  
A: Yes, future enhancement. Pinleaf can include PSRAM allocation hints.

**Q: What about hardware revisions of same platform?**  
A: Platform ID can include board revision (e.g., "ESP32-C3-DevKitC-02").

**Q: Should partition sizes be user-editable in export dialog?**  
A: Yes, for advanced users. Toggle "Expert Mode" to show sliders.
